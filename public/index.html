An AI travel agent that quotes and books, not just chats

A sales assistant for an Uzbekistan tour operator. It recommends one of 14 real tours, quotes exact prices from an API (never from the model), and saves a booking request with a reference number. In English, Russian and Uzbek.

Prices can’t drift

Every number comes from /api/quote: tier by group size, hotel class, single supplement, 10+ groups flagged as a starting price.

Real lead capture

Summary card → “Shall I send this request?” → POST /api/requests → reference number like FT-MW3QD2VY45I.

Three languages

Answers and tour cards fully in the traveller’s language; only tour names stay in English.

Safe by design

No invented tours or discounts, no payments in chat, visa answers point to e-visa.gov.uz, off-topic requests politely declined.

The dip in run 3a came from a pure UI change (new tour cards). The regression suite caught it before launch.

  • Biggest single fix: moving prices out of the prompt into a tool call, and giving the agent a real “submit request” action.
  • Quote first, ask later: dates don’t change the price, so the agent quotes immediately and asks at most one question.
  • Customer language rules: no “API”, “catalogue” or repeated disclaimers in front of travellers.

API

Endpoints

/api/tours · /api/quote · /api/departures · POST /api/requests · /api/health

Hardening

Per-IP rate limit, idempotency keys (no duplicate leads on retries), honeypot, Telegram alert to sales.

Stack

Node 20 serverless on Vercel, zero runtime dependencies, Upstash Redis, 16 tests.
